# Device Storage & Cookies Notice

Effective October 20, 2026 · Version 2026-10-20

## Scope

This notice describes device/browser storage used by Pulse and the separate public policy pages. It supplements the Privacy Policy and Consumer Health Data Privacy Policy. A separately operated marketing website or a newly introduced integration has its own disclosures; changes affecting Pulse data will be disclosed before activation as required.

## Native app

Pulse uses platform secure storage for authentication sessions, cached records and pending tracking events. Local app preferences support notification privacy, biometric lock and related settings. Device/OS settings may also affect backups and storage. Temporary generated PDF files are removed after sharing completes; copies you save remain in your selected destination. Optional substance photos are stored per account/substance on this device, not uploaded to Pulse or an image-generation provider. Unconfirmed creation requests retain their identifiers and original input in private device storage so interrupted saves can be retried without duplicating records. Successful requests are cleared; remaining requests can be included in an account export from that device.

## Web app

The web app uses browser storage for sign-in sessions and app state. This is not the native secure-store implementation. Signing out ends local authenticated use; account deletion removes associated synced data. Clearing browser storage can remove cached and unsynced information and sign you out.

## Policy pages and optional tracking

The public policy pages do not set cookies, run JavaScript analytics, embed third-party fonts or advertising, or load tracking pixels. Cloudflare hosts these pages and processes request/connection information such as IP address and browser/request metadata for network delivery and security under its provider obligations. The static host does not submit forms, receive account credentials, fetch Pulse health records or intentionally record request bodies.

Pulse does not include an advertising identifier, advertising network or behavioral analytics SDK. Providers and operating systems may still process the operational/security information described in the Privacy Policy. Any future non-essential tracking requires appropriate disclosure and consent before activation where required; it will not be silently enabled by a policy update.

## Controls

Use Pulse and device settings to manage optional permissions and privacy controls. Clear browser storage to remove local web state; this can discard unsynced records and sign you out but does not delete your server account. Uninstalling the app is not a server-account deletion request, and operating-system secure storage/backups can have separate lifecycles. Use Account & Privacy or the external deletion contact to delete associated active account data. Revoking calendar permission does not necessarily remove events already created; remove Pulse-created calendar events before disconnecting/deleting if you want those copies removed.

## Interrupted feedback submissions

If a feedback submission is interrupted, its original message, category, follow-up consent choice, version/build, platform and request identifier remain in private storage on this device so the same ticket can be retried without duplication. The saved retry record is scoped to the signed-in account and is removed after confirmed submission or account deletion. A message that has never been submitted remains only in the open form and is discarded if you choose to close it.
