# Pulse Design Language v1

Pulse should never feel like a generic health, habit, medication, or fitness tracker. The interface is a living scientific instrument for understanding a user-entered routine.

## Core principles

1. **Signal over decoration**
   Visual elements should communicate time, state, rhythm, supply, history, or progress. Avoid ornamental sci-fi effects that do not carry meaning.

2. **Calm instrument-grade hierarchy**
   Numbers, times, quantities, and percentages use strong alignment, tabular numerals, restrained emphasis, and predictable spacing.

3. **Rhythm is a first-class visual language**
   Schedules should appear as patterns across days, not just as text labels. Protocol Map and Routine Fingerprint are foundational motifs.

4. **State should feel alive**
   Today changes as the day progresses. Completed actions should visibly settle. Low supply and missed activity should surface quietly but clearly.

5. **Privacy is product identity**
   Biometric lock, discreet notifications, privacy-safe widgets, and export/delete controls are part of the core product experience.

6. **Descriptive, never prescriptive**
   Pulse may summarize user-entered schedules, history, inventory, and arithmetic. It must not recommend treatment, dosing, stacks, or clinical changes.

## Signature surfaces

- **Protocol Map** — seven-day routine density and upcoming schedule view.
- **Pulse Brief** — compact command-center summary on Today.
- **Activity Signal** — seven-day history waveform on Timeline.
- **Routine Fingerprint** — item-by-day scheduling pattern on Insights.
- **Supply runway** — inventory translated into user-entered-dose runway without treatment recommendations.

## Motion

Motion should be subtle and functional:
- press feedback on actions,
- state transitions for logging/completion,
- restrained progress movement,
- no continuous decorative animation that distracts from the protocol.

## Visual rules

- Dark scientific base with icy-blue active signals.
- Use accent borders sparingly for active/meaningful surfaces.
- Prefer tracks, nodes, rails, signal strips, and mapped relationships over stacks of generic cards.
- Preserve generous breathing room.
- Use layered navy gradients and restrained cyan glow to match the approved visual direction. Keep text contrast and state hierarchy clear; avoid effects that obscure information.
- Numeric UI should use tabular numerals where supported.
