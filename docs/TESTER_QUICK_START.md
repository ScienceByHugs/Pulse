# Pulse by SBH — beta tester checklist

Use fictional records. Install the latest assigned build in TestFlight and note its build number. Build 9 contains the ten tracking improvements; the newer administration labels, site dropdown, substance picker, artwork and policy pages remain local and are not in that build.

1. Sign in; change your profile photo; sign out and back in. Expect the login page and only your own records.
2. Create a sample protocol and a fictional substance. Set morning/evening times, an entered amount of 1 unit and a container total of 30 units. Confirm each time is tracked independently.
3. Log morning, Undo, Skip, Undo, then Log again. Verify only one active morning record and one inventory decrement. Logging morning must not complete evening.
4. Load Today online, enable airplane mode, log evening, close/reopen and reconnect. Expect the original record time, one synced record and one stock decrement. Repeat with an offline Undo.
5. Duplicate the protocol. Expect a paused copy without copied inventory/history. Review before activating.
6. Enter container date limits; verify expired containers are not automatically selected. Estimates describe your entered routine.
7. Enable notifications. Verify reminder arrival and tap it to open/highlight the correct scheduled entry. Log/skip the entry and check future reminders are suppressed.
8. Search/filter Timeline. Save, edit and delete a fictional check-in. Generate a PDF with notes excluded, save to Files and inspect the contents.
9. Use a second account on the same device. Check records, cached entries, photos and sync state never mix. Never share login credentials with another tester.
10. Only on a separate disposable account: export data, delete the account and verify it can no longer sign in. Do not delete the Apple review account.

## Send useful feedback

Use TestFlight → Pulse → Send Beta Feedback. Include build number, iPhone/iOS version, steps, expected result and actual result. Say whether you were offline. Include a screenshot only after removing private health data and credentials.

Never post passwords, confirmation links, personal health data or identifiable exports in GitHub issues or screenshots.
